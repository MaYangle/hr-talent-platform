# 部署与运维

## 运行方式

应用使用一个 Python HTTP 进程和一个后台 Worker 线程。SQLite、原始附件、任务和审计保存在服务端数据目录中。浏览器只负责交互，不是团队资料的持久化位置。

```bash
python server.py --host 127.0.0.1 --port 4173
```

默认只允许本机访问。前台运行时按 Ctrl+C 停止；通过 Windows 启动脚本启动的服务在后台运行，可以双击根目录的 `stop_windows.cmd` 停止该目录启动的后台服务。

## 环境变量与启动保护

进程配置由 `talent_hub/config.py` 统一校验；全部变量、默认值与范围见[配置参考](CONFIGURATION.md)和根目录 [.env.example](../.env.example)。原生 Python 启动不会自动加载 `.env`，Compose 仅传入 compose.yaml 中明确列出的变量。

启动顺序是：取得工作区独占锁 → 初始化 / 恢复数据库任务 → 绑定 HTTP 端口 → 启动 Worker。相同数据目录不允许两个实例同时运行，端口绑定失败也不会留下额外 Worker。

PowerShell 设置方式：

```powershell
$env:TALENT_DATA_DIR = 'D:\TalentHubData'
.venv\Scripts\python.exe server.py
```

Linux / macOS 设置方式：

```bash
export TALENT_DATA_DIR=/srv/talent-hub/data
.venv/bin/python server.py
```

业务数据目录应与源码分开，不放在 Git 仓库或自动同步的代码目录内。

## 健康检查与停止

- `GET /health/live`：确认 HTTP 进程存活，返回应用标识和版本，不返回业务数据。
- `GET /health/ready`：数据库可读且 Worker 存活时为 200，否则为 503；不调用模型或 OCR。
- `GET /api/status`：查看是否需要首次管理员初始化。

可使用 `curl --noproxy '*' http://127.0.0.1:4173/health/ready` 检查本机服务。健康检查通过不能证明模型、OCR 语言数据、磁盘剩余空间或业务结果全部正常。

原生前台服务收到 Ctrl+C、容器收到 SIGTERM 后会停止接收新任务，等待当前文档页或模型请求结束；未完成任务重新排队，已保存结果保留。容器默认提供 150 秒停止宽限期；提高模型超时后应相应提高 `stop_grace_period`。Windows 后台停止脚本会终止该目录对应的服务进程，运行中任务在下次启动时恢复。

工作区锁由操作系统持有，进程退出后自动释放。不要通过手工删除锁文件来并发启动第二个实例。

## 内网与 HTTPS

先在服务器本机创建管理员。需要内网访问时，设置实际访问地址的主机白名单，再监听网络接口：

```powershell
$env:TALENT_ALLOWED_HOSTS = 'talent.internal'
.venv\Scripts\python.exe server.py --host 0.0.0.0 --port 4173
```

这里的 `talent.internal` 需要由部署方提供 DNS 或 hosts 解析。使用 IP 访问时应改为服务器实际 IP。首次管理员初始化仍必须从服务所在电脑的回环地址完成。

面向团队提供服务时，建议通过 HTTPS 反向代理访问。代理须保留 Host，并将请求转发到应用；设置 `TALENT_SECURE_COOKIE=1`，并把实际域名加入白名单。TLS、证书更新和防火墙由部署环境配置。应用自带的 Python HTTP 服务不提供 TLS 终结或高可用能力。

## OCR

- Windows：使用系统的 `Windows.Media.Ocr`，需要已安装相应的 OCR 语言包。
- Linux：安装 Tesseract 以及所需语言数据；默认使用中文和英文。
- macOS：当前没有内置 OCR 适配器，请先将扫描件转换为带文本层的 PDF。
- Docker 镜像包含 Tesseract 中文与英文依赖。

OCR 或文档解析失败不会删除已保存原件。可修正环境后重试，也可对照原件手工建档。

OCR 与简历字段提取是两个阶段：OCR 将扫描图片转成文字；规则或本地大模型再从文字中识别字段。没有 OCR 引擎时，有文字层的 PDF、DOCX 和 TXT 仍可处理；纯扫描 PDF 需要先配置本地 OCR，否则无法获得可供规则 / 模型读取的文本。

## 本地模型

新工作区默认使用模型 `Qwen/Qwen3.8-27B` 和接口 `http://172.30.0.101:20001/v1` 进行简历字段提取；岗位匹配仍默认使用证据规则。管理员可在系统设置分别更改简历字段提取模式、岗位匹配模式、模型接口和模型名称；两个模式互不影响。接口需要兼容 OpenAI 的 `/chat/completions`。默认允许 `localhost`、`127.0.0.1` 和 `::1`；本项目另显式允许该指定内网接口，其他非回环地址仍被拒绝，且不跟随 HTTP 重定向。指定接口使用明文 HTTP，应仅部署在受控内网。

模型请求由服务器发出，因此不需要浏览器 CORS。认证密钥通过服务进程环境变量 `TALENT_MODEL_API_KEY` 提供，不保存在工作区备份中。VS Code 扩展的模型配置和认证不会自动共享给此 Python 应用；模型返回 401 时需向模型服务管理员获取该应用可用的密钥，并在启动服务的进程环境中设置。模型输出会经过字段和原文引用校验，分数由程序按岗位权重计算。简历模型提取会将原文发送到配置的模型端点，仅采用能匹配回原文行的字段供人工核对。

Docker 中的回环地址指容器本身。使用模型模式时，模型须与应用共享该网络命名空间；如果模型运行在宿主机，当前优先使用原生 Python 部署。基础档案和证据规则匹配不受模型是否存在影响。

## Docker 与数据卷

```bash
docker compose up --build -d
docker compose logs -f
docker compose down
```

Compose 默认只映射本机 4173，数据保存在 `talent-data` 具名卷。`docker compose down` 不会删除具名卷；请勿在需要保留资料时使用 `down -v`。

容器以非 root 用户运行。数据库使用 SQLite WAL，请使用单个应用实例连接该数据卷；不支持通过多个容器同时运行 Worker。数据目录应放在本机可靠文件系统，避免云同步目录、网络共享盘或不支持锁语义的存储。

## 备份、恢复与升级

管理员在系统设置中导出完整工作区备份。备份包括业务记录、简历原件、账号密码哈希和审计，不包含进程环境中的模型密钥。备份应保存在受控位置，并制定保留周期。

恢复步骤：

1. 导出并妥善保存当前备份。
2. 在管理员设置中选择要恢复的工作区备份。
3. 输入“替换工作区”确认。
4. 恢复完成后，全部会话失效，使用备份中的账号重新登录。

恢复不是旧附件的即时物理清除工具；未被恢复记录引用的磁盘附件不会自动删除。需要制定单独的保留及清理策略。

升级前先备份并停止旧服务，更新源码和依赖后再启动。修改数据结构时应保留迁移记录和恢复路径，不能直接清空数据库。已运行任务会在服务重启后重新排队，已保存的成功匹配项可继续使用。

## 常见问题

| 现象                         | 处理方式                                                                                                             |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 页面无法连接                 | 确认服务仍运行；检查地址和端口，或前台执行 `python server.py` 查看错误                                               |
| 4173 被占用                  | 用 `--port` 或 `TALENT_PORT` 选择其他端口；确认旧服务与目标数据目录                                                  |
| 数据目录已被使用             | 停止占用该工作区的旧实例，或为新实例设置独立 `TALENT_DATA_DIR`；不要删除锁文件强行并发                               |
| ready 返回 503               | 检查服务进程和数据目录权限，确认 Worker 未退出，必要时备份后重启                                                     |
| 主机名未授权                 | 将实际域名或 IP 加入 `TALENT_ALLOWED_HOSTS` 后重启                                                                   |
| 登录后请求校验失败           | 刷新页面，重新登录；检查代理是否保留 Host，页面是否来自同一来源                                                      |
| 修改出现 409                 | 其他用户已保存新版本，刷新并重新核对后保存                                                                           |
| 模型任务失败                 | 检查模型服务、地址、名称及认证；成功项保留，可重试失败项                                                             |
| 一份文件失败后有文件尚未保存 | 查看上传弹窗中的逐项原因；成功文件已保存，修正失败文件后重新选择                                                     |
| 上传后未获得字段             | 查看逐文件错误；核实原件是否含文本、格式是否完整及 OCR 环境是否可用                                                  |
| 需要重置管理员密码           | 优先使用另一个管理员账号重置；也可恢复已妥善保管且已知管理员密码的备份。当前无无凭据自助重置入口，不直接编辑密码哈希 |
| 切换地址后看不到原资料       | 检查运行服务使用的 `TALENT_DATA_DIR` 是否改变；浏览器地址不会决定服务端资料目录                                      |
| 测试被公司代理影响           | 浏览器测试会为回环请求设置代理绕过；独立 curl / 运维工具也应绕过回环代理                                             |

## 当前运行边界

当前提供单组织、单实例的自托管工作区。高可用、外部消息发送、PostgreSQL 和企业单点登录未实现。请根据组织的数据处理要求配置账号、网络、备份和保留策略。
