# 使用手册

本手册面向管理员、HR、招聘经理和面试官。安装和启动命令见[README](../README.md)，数据位置及备份见[部署与运维](OPERATIONS.md)。

左侧保留四个核心入口：人才库、简历导入、招聘、系统设置。招聘入口内按岗位、匹配、跟进、面试、统计分栏完成流程；非写入角色只显示其可用功能。

短选项（状态、任职情况、模型模式、导入决定等）直接点击选择；面试评分点击 1–5 分即可选中，再点已选分数可清空。日期可直接输入或使用“今天 / 明天”，快捷选择保留已输入的时间。人才、岗位、负责人等关联记录仍使用列表选择。选项即时反映在表单中，最后点击保存一次性提交整份记录；关闭未保存表单不会自动提交。保存期间禁止重复提交，权限、修订冲突和完整性规则不变。

## 1. 建立工作区

1. 在服务所在电脑上打开 http://127.0.0.1:4173 。
2. 创建管理员账号，填写登录名、显示姓名和至少 10 个字符的密码。
3. 在系统设置中为同事创建独立账号，选择合适角色。
4. 通过简历导入或新建档案开始录入资料。

首次初始化不会创建候选人、岗位或面试记录。界面中的数量和图表来自实际保存的数据，空工作区显示空状态。

## 2. 导入简历

在“简历导入”选择来源并上传文件。支持 PDF、DOCX 和 UTF-8 TXT；默认每批最多 50 份、每份不超过 20 MiB；管理员可通过进程配置调整，弹窗展示当前限制。通过文件校验的文档会先保留原件，再由后台任务提取文本。未通过格式或大小校验的文件显示“未保存”，不会中止后续文件。全部上传后可选择“完成并查看任务”。

每份文件分别显示文件保存、解析、待核对、疑似重复、失败和人工处理状态。离开页面不会取消任务。扫描 PDF 可使用本地 OCR；OCR 不可用或文件解析失败时，原件仍可供查看，任务可重试，也可手工建档。

管理员在系统设置分别选择简历字段提取、岗位匹配方式和扫描件 OCR。简历设为“本地大模型填表”后，新上传按“提取原文 / 可选 OCR → 规则提取 → 本地模型填表 → 人工核对”处理；岗位评分设置不会改变简历导入。每个采用的模型字段必须携带可验证的页、行和原文片段，值必须来自该片段。未提及的信息保持空白，目标岗位或城市不能用当前任职信息替代；不自动推断薪资或个人身份属性。规则提取模式不调用模型。

保存配置前可点击“测试模型连接”验证当前填写的地址和模型 ID。测试不会保存设置，也不会发送简历内容；成功表示服务认证通过且模型返回了内容。401 会提示检查服务进程的 `TALENT_MODEL_API_KEY`。

OCR 仅把扫描 PDF 图片转成文字。没有可用 OCR 时，TXT、DOCX 和带文字层 PDF 仍可用规则或模型提取；纯扫描 PDF 不含可解析文字，不能只靠规则补出内容。

模型离线或响应无效时，保留原件和规则结果，在核对页显示警告；可以人工继续处理，或恢复模型后点“重新提取”。已有待核对任务也可重新提取；重新提取会替换该任务的解析值，不保留尚未提交的手工修改，但不会改动已建档的人才。已处理任务不能重新提取。

打开“核对 / 比较”逐项检查提取字段。字段引文可定位到 PDF 页或 DOCX / TXT 段落组及行；提取文本与原始附件应一起核对。完成核实后保存档案。

档案与导入核对按联系意向、任职能力、选填信息分组，顶部实时提示缺失或无效信息；仍允许保存待补全档案，服务端完整性规则不变。点击导入字段可突出对应证据。匹配任务创建时可展开查看可匹配人数、待处理名单和补全入口。

### 重复审查与简历版本

系统使用文件 SHA-256、标准化电话和邮箱、姓名与公司组合提供重复提示。单纯同名不会自动关联，联系方式也不设置全局唯一约束。

遇到疑似重复时，比较双方字段，然后明确选择：

- 关联到既有人才，追加简历版本；
- 确认是独立的人才，另建档案；
- 跳过本次导入。

追加版本保留主档已核实字段。需要改用该版本的解析值时，在档案的“简历版本”中选择“采用本版解析值”，确认后重新核实字段。

## 3. 维护与查找人才

人才库支持姓名、公司、岗位及简历关键词搜索，也支持城市、来源、状态、技能、学历、目标岗位、经验、更新时间和最新简历日期的组合条件。可以调整排序、每页数量；筛选仅用于当前页面，不再保存个人或团队视图。招聘入口内通过岗位、匹配、跟进、面试标签切换同一工作流程，统计用于运营复盘。

点击人才姓名打开档案，可维护字段、人才库状态，查看履历证据、简历版本、岗位流程和面试记录。缺项允许保存为待补全；“完整”与“人工已核实”是不同状态。

“未任职”应通过任职状态明确选择，不必虚填当前公司与岗位。未知、待确认、无效联系方式等占位内容不会计为完整字段。性别不作为结构化档案字段、筛选项或评分输入。月薪与年薪独立选填，均为人民币税前，年薪表示年度总包。

多人同时编辑时，如果另一个人已保存新版本，服务器会提示冲突。刷新并重新核对后再保存，避免覆盖他人的修改。

## 4. 建立岗位并分配跟进

在“岗位与 JD”创建岗位，导入文件或粘贴职位描述，逐项确认要求、是否硬性和评分权重。发布后生成不可变 JD 版本；后续调整会生成新版本。

将候选人加入岗位流程，选择阶段、负责人、下一步具体动作和截止时间。进行中的流程必须有责任人及下一步；已录用或已结束时填写结案结果。

同一人可以参与多个岗位，每个岗位的阶段独立管理。人才库全局状态与岗位阶段也分别保留。工作台可进入本人待办、逾期待办和待反馈面试。

## 5. 安排面试与收集反馈

先建立岗位候选人流程，再从“面试安排”关联该流程，填写轮次、类型、开始时间、时长、面试官、反馈跟进负责人和截止时间。保存时会检查面试官及候选人的日程重叠。

评价包含总体、专业能力、沟通表达和问题解决，接受 1–5 分或留空，并可记录反馈和下一步建议。面试官只能填写本人被安排面试的反馈。反馈到期未完成会在工作台和列表中提示。

提醒在应用内展示，不会自动发送邮件或联系候选人。

岗位跟进列表可直接安排面试，自动带入关联申请。面试表单分为安排信息与评价反馈，可记录面试方式、地点或会议链接；面试官只能查看、不能修改安排。已完成反馈保存后，HR 可继续人工更新岗位阶段，系统不会自动推进阶段或修改人才库状态。

## 6. 运行岗位匹配

选择具体 JD 版本和匹配范围：全部已核实完整档案、当前人才筛选结果，或该岗位的人才池。创建任务后可离开页面，后台逐人保存结果。

结果显示硬性条件、证据分、覆盖度、逐项原文、差距与待确认项。缺少信息显示待确认；只提到其他技能不能据此断定不具备所需技能。覆盖度不足 70% 时，分数标为信息不足。

每次任务固定 JD、规则、模型配置、档案修订和选定简历版本。历史结果不会随最新资料变化。部分失败时保留成功结果，可重试失败项；评分规则更新后应创建新任务。

默认使用证据规则。管理员连接本地模型后，可使用真实模型辅助逐项分析；模型不可用会显示错误，不自动转用外部服务。最终决定由 HR 查看证据并作出。

## 7. 查看运营指标与导出

运营看板按候选人入库日期队列、岗位和渠道筛选，显示新增趋势、阶段人数与转化、停留时间、渠道质量、逾期事项和导入质量。页面会显示统计口径；点击指标可下钻到对应人才。

有导出权限的用户可导出当前人才筛选结果、固定匹配快照和运营汇总。管理员可以导出完整工作区备份。导出记录会进入审计。

人才列表、匹配明细和运营汇总支持带 UTF-8 BOM 的 CSV，可使用 Excel 打开；匹配与运营仍保留 JSON 导出。运营 CSV 包含筛选条件、统计时点、口径与解析任务分母。界面提示已生成文件不代表操作系统已完成落盘，请查看浏览器下载列表。

## 8. 角色权限

| 角色     | 可执行操作                                         | 主要限制                                         |
| -------- | -------------------------------------------------- | ------------------------------------------------ |
| 管理员   | 业务操作、用户、配置、审计、备份恢复               | 不能禁用本人或移除本人管理员角色                 |
| HR       | 档案、薪资、原件、导入、岗位、匹配、面试及业务导出 | 无用户管理、系统配置、全局审计和备份恢复权限     |
| 招聘经理 | 脱敏档案、岗位流程、面试和团队统计                 | 隐藏联系方式、简历正文、薪资、原件，禁止导出     |
| 面试官   | 分配给本人的人才、岗位流程与面试反馈               | 不可读取敏感字段，不能更改面试安排或访问他人面试 |

权限由服务器校验。使用独立账号有助于准确记录实际操作者，不应多人共用一个账号。
